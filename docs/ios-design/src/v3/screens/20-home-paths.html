Developer notes

Purpose

One question, one answer: what do I draw next? The hero answers it in one tap; the path underneath shows where it leads §29. No streaks, XP or goals — nothing on this screen can go down §30.

Layout

  • Scrolling body between the status bar and the three-tab bar, 20 pt gutters, 12 pt between blocks. Title 36/800; the gold chip on the right is a fact (sketchbook pages), tappable → sk-book.
  • .card--hero: eyebrow "Continue · Houses" 12/800, title 24/800, meta 15/600 at 78 % white, a 96 pt white .thumb of the next lesson's finished drawing (stroke 30 on the 1000 canvas), white 64 pt primary with green text — the only primary on the screen.
  • Path header: eyebrow "Houses · 2 of 10 drawn" and a blue text link "All paths" → hp-paths.
  • .path: all ten lessons as 84 pt nodes, rows alternating --x ±40 pt, labels 16/800 + 13/600 on the outer side, 22 pt between rows. Node art = the lesson's finished drawing at 60 pt, stroke 34. The list ends with "See the whole path" → hp-path.
  • Lina is not here. She belongs to onboarding, the narration chip and completion; a tutor on every launch reads as mascot motivation §30.

States & interactions

  • in-progress — hero = first not-done lesson of currentPathId. Hero button and the green node → hp-preview; a gold node → hp-preview for that lesson (draw it again); a grey node → hp-path with the locked sheet naming the lesson that comes first.
  • first-time — straight from ob-ready: one line under the title, eyebrow "Start here", node 1 current, 2–10 locked, an honest empty-sketchbook line instead of the chip.
  • Path finished (not drawn): the hero reads "You have drawn every house in this path" with Choose another path → hp-paths; see hp-path variant complete.
  • Nothing animates on appear except the current node's slow halo (2.2 s, off under Reduce Motion). Progress changes only after a completion.

What changed in v3

  • White page; the hero is a filled green banner instead of a bordered card, with a white thumbnail and a white-on-green button Duolingo.
  • The path cards and "More paths" button are gone: the current path is drawn as nodes on the home screen, so progress is seen as drawings rather than read as "2 of 10". Other paths sit behind one text link.
  • Type up a size everywhere (title 36, hero title 24, labels 16); tactile 4 pt-edge buttons; gold = drawn, green = next, grey = later.

SwiftUI mapping

TabView { NavigationStack { LearnHomeView() }; SketchbookView(); SettingsView() }
ScrollView { LazyVStack(spacing: 12) { TitleRow(pages: progress.photoCount); HeroCard(next); PathHeader; PathView(path, progress) } }
LessonNode(state: .done(date) | .current | .locked, drawing: tutorial)   // Canvas of the tutorial's strokes

Accessibility

  • VoiceOver: hero is one element — "Continue. Small Cottage, lesson 3 of 10, Houses, about 4 minutes, 7 steps", action "Start drawing". Nodes: "Simple House, drawn 3 September, button" / "House From an Angle, locked, after Small Cottage". The halo is decorative.
  • Dynamic Type: labels scale, nodes and thumbnail stay fixed; at accessibility sizes node rows drop the zig-zag (--x: 0) so labels get the full width. Nothing under 13 pt; 13 pt only on node meta.
  • Tap targets: nodes 84 pt, hero 64 pt, "All paths" has a 44 pt hit area.

Open questions

  • Ten nodes on Home is a long scroll once a path is long; cap at the current node ± 3 with "See the whole path"? Shown: all ten, because a path is 8–12 lessons.
  • Trees 4 of 8 (six sketchbook pages) vs the brief's "Trees lesson 1" — carried over from v1, still open.

Developer notes

Purpose

Switching subjects freely, with progress kept per path §6. Pushed from "All paths" on Home; the tab bar stays because this is still the Learn stack.

Layout

  • Inline nav bar "Paths" with a back chevron → hp-home; one 17/400 line of intro.
  • Path card (.hp-pcard): 2 pt border with a 3 pt edge, radius 24; a 72 pt white paper .thumb with the subject's drawing (stroke 34); title 20/800; one 13/600 description; then either an 8 pt progress bar + "2 of 10 drawn · Next: Small Cottage", or a grey chip "Not started · 8 lessons". Chevron at 25 % ink. Minimum height 100 pt.
  • The current path (currentPathId) gets the 2.5 pt green border — the same "selected" language as onboarding's choice rows.
  • Coming later: a .list--soft with 40 pt icon tiles and no chevron, no button semantics. Icons come from the shared sheet and five screen-prefixed ones (hp-i-*).

States & interactions

  • Any open card → hp-path for that path (started or not). Tapping a card does not change currentPathId; starting a lesson does.
  • "Coming later" rows are inert. No notify-me, no sign-up §32.
  • Order: started paths by most recent completion, then unstarted paths in catalog order, then the unpublished list from the catalog's status.
  • One-time first-visit header. The first time an early learner (three or fewer lessons done) is sent here from a lesson-complete screen's "Not now" or "Done" (see sk-complete), this screen opens with a header above the intro line: a written title, "N paths to explore" — N counted from the shipped catalog only, never a placeholder or "Coming later" row — and a row with Lina's .face and one line she says once, "There's a lot more to draw here. Pick whatever you like next." (app line paths-welcome). The current path keeps its ordinary green outline and "Now" badge underneath; the header adds to the screen, it does not change how any card reads. The header is shown once per learner — gone as soon as they leave this screen, never shown again after that, and never shown to a learner who did not arrive this way (opening "All paths" from the tab bar or from Home never triggers it).

What changed in v3

  • Rows became cards with a drawing of the subject instead of a 44 pt icon tile — the paper is the product, so each path is introduced by what you will draw.
  • Two states instead of three chips: a bar with a count, or "Not started". Unpublished paths moved out of the cards into a soft list.
  • The iPad variant was dropped in v3; the list simply holds a 700 pt measure on wide windows.

SwiftUI mapping

List-free ScrollView { VStack(spacing: 12) { ForEach(catalog.paths) { PathCard(path, progress) } ; ComingLaterList(catalog.unpublished) } }
PathCard: NavigationLink(value: Route.path(id)) { HStack { DrawingThumb(path.coverLessonId); VStack { title; description; progressOrChip }; chevron } }

Accessibility

  • VoiceOver: "Houses, 2 of 10 drawn, next Small Cottage, button" — the bar is hidden because the label says it. Later rows: "Landscapes, coming later" with no button trait.
  • Dynamic Type: text scales, the 72 pt thumbnail stays; at accessibility sizes the card stacks the thumbnail above the text.

Open questions

  • Which drawing represents a path — lesson 1, the destination, or a catalog coverLessonId? Shown: lesson 1 for Houses, a representative sketch for the rest.

The destination is drawn large before the path begins; every lesson is a node. Locked: a detent sheet names the lesson that must come first. Complete: gold everywhere and one green button to choose the next path.

Developer notes

Purpose

§29 asks for ordered progression, the next lesson, completed and locked lessons, and a destination example. All five are on the first fold: the big drawing, the count, two gold nodes, the green one.

Layout

  • Inline nav bar "Houses", back → hp-home. Tab bar kept: still the Learn stack.
  • Destination sheet (.hp-dest): 196 pt white paper, radius 28, 2 pt line; the last lesson's drawing at 220 pt (stroke 14); gold chip "Where this path leads" top-left; "Lesson 10 · Small Street Scene" 13/600 bottom-left. Not tappable — it would land on a locked lesson.
  • Title 30/800 with the full paths.json.description at 15/600 — the one place it is not truncated. Then "2 of 10 drawn" 17/700 with "Next: Small Cottage" and a 12 pt green bar. No percentage.
  • The path: the same .path as Home, all ten nodes, labels carrying the full date ("Drawn 3 September") or the unlock reason. 22 pt between rows, ±40 pt zig-zag.

States & interactions

  • default — 2 done, 3 current, 4–10 locked. Gold and green nodes → hp-preview; a grey node raises the sheet.
  • locked — a detent sheet (.presentationDetents([.height(320)])) with the locked drawing greyed in a 72 pt tile, "Finish Small Cottage first.", one line on why, the primary "Go to Small Cottage" → hp-preview, and "Not now". Swipe or tap outside dismisses. No unlock offer: locking is a teaching decision, not a paywall §6. The tapped node stays pressed (--surface-2) behind the sheet.
  • complete — the destination sheet turns gold-tinted with "10 of 10 drawn"; headline "You have drawn every house in this path."; the one primary is Choose another path → hp-paths, then a text button to sk-book; the bar and every node are gold with dates.
  • Returning from a completion, scroll to the new green node (scrollTo(id, anchor: .center), 0.3 s; instant under Reduce Motion) — the only motion here besides the node halo.

What changed in v3

  • The numbered list became the node path Duolingo; each node carries the lesson's drawing, so the whole path reads as a set of pictures the learner will own.
  • The destination card became a large drawing on paper at the top instead of a 112 pt thumbnail in a bordered card.
  • Complete now has a green primary (choose another path) — the v1 version had none; a finished learner should be pointed somewhere.

SwiftUI mapping

ScrollViewReader { ScrollView { VStack(spacing: 12) { DestinationSheet(lastLesson, done: allDone); PathTitle; PathProgress; PathView(path, progress) } } }
.sheet(item: $blocker) { LockedLessonSheet(locked: lesson, blocking: firstUnfinished(before: lesson)) }
isUnlocked(id) = index == 0 || lessonIds[..<index].allSatisfy(progress.isDone)   // keyed by lessonId, never index

Accessibility

  • VoiceOver node labels carry the reason: "House From an Angle, lesson 4 of 10, locked. Finish Small Cottage first. Button." — no one needs the sheet to learn it. The sheet takes focus on appear and returns it to the node.
  • Reduce Motion: the halo becomes a static ring; colour, the check badge and the label all carry the state, which also covers colour-blind learners.
  • Dynamic Type: labels scale and the zig-zag flattens at accessibility sizes; the sheet's button keeps its 64 pt floor.

Open questions

  • Should a done node show the learner's photographed page instead of the tutorial drawing? Shown: the drawing, so the path still reads as a curriculum.
  • Is the destination always the last lesson, or a catalog isDestination flag? Last lesson assumed.

Reference and finished drawing side by side, so the learner sees the translation from the real thing to pen before committing four minutes. Resume: the done steps are shown at full strength, the rest faded.

Developer notes

Purpose

The four things §29 asks for — reference, final sketch, time, one objective — plus the honest "what you need", because the whole product depends on paper being in front of the learner §4. One green button.

Layout

  • Inline nav bar "Houses · 3 of 10", back → hp-path. Portrait only; the player handles landscape.
  • The pair: two 1:1 tiles, 170 pt, 12 pt apart, 13/600 labels above. Reference (.photo) left, the finished drawing on white paper right (.canvas-frame, radius 18, strokes 16/12 on the 1000 canvas). Credit at 13 pt under the pair.
  • Title 30/800; chips: clock "About 4 min · 7 steps" and a complexity chip with five 6 × 12 pt pips (lessons.json.complexity, 1–5). Objective on a soft card at 17/500. Then the pen + paper line and Lina at 64 pt with one line on the method.
  • The primary sits in a fixed .bottom-area, never inside the scroll, so it is always visible on the smallest phone.

States & interactions

  • default — Start drawing → pl-player variant drawing. Back → the path.
  • resume — a run of this lesson was left through pl-leave. The drawing tile shows done steps at full strength and the rest at 22 %; chips say "Paused at step 3 of 7" and the time left; seven .segments; the objective card becomes the next step's instruction; Lina's intro is dropped. Primary Continue from step 3; a text button Start over clears the saved position and starts at step 1 (no confirmation — nothing is lost but a position).
  • Already drawn (not shown): the same layout with a gold "Drawn 3 September" chip and the primary reading Draw it again; a second page is added to the sketchbook, never replacing the first §7.
  • No reference photo: the pair collapses to one full-width drawing; no empty grey tile, no credit line.

What changed in v3

  • The drawing tile is white paper with a 2 pt line instead of cream card; a bigger title and a 64 pt tactile primary.
  • Complexity is now shown (pips, never a score of the learner) beside time and steps, so an adult can judge the four minutes.
  • The v1 replay variant is replaced by resume, the state the player's leave sheet actually produces.

SwiftUI mapping

VStack(spacing: 0) { ScrollView { ViewThatFits { HStack { ReferenceTile; DrawingTile(upTo: resume?.step) }; VStack { … } }; title; chips; ObjectiveCard; NeedRow; if !resuming { TutorLine } }
  BottomArea { Button(resuming ? "Continue from step \(n)" : "Start drawing"); if resuming { Button("Start over") } } }
resume ← PlayerViewModel.savedPosition(lessonId)   // set by pl-leave, cleared on finish or Start over

Accessibility

  • VoiceOver: "Small Cottage, lesson 3 of 10 in Houses. About 4 minutes, 7 steps, complexity 2 of 5." The photo needs a real label from the catalog (proposed required reference.alt); the drawing is labelled "The finished pen drawing: a cottage with a chimney and a bush".
  • Dynamic Type: the pair becomes one column at accessibility sizes; chips wrap; the objective never truncates; the button grows and keeps its 64 pt floor.
  • Reduce Motion: the drawing is static in every case — it never animates on appear. That is the player's job.

Open questions

  • The time label is computed from estimateLearnerSeconds; today's formula gives "about 1 min" for Simple House, not 4. M6 times real lessons.
  • simple-house.json has no reference block yet, so the first real lesson would render the no-photo state.
