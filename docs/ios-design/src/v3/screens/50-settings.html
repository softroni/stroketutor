Developer notes

Purpose

§29 “Minimal; speed/accessibility/privacy/reset where useful.” Every row changes how a lesson plays, makes the app readable, or answers a privacy question. No account, no sign-in, no paywall row §30.

Layout

  • 36/800 title, then four .list cards (white, 2 pt --line border, radius 24) with 12/800 uppercase eyebrows at 55 % ink. Rows ≥ 60 pt, 18 pt side padding, 14 pt gap.
  • Icon tiles are 40 pt .leading squares, radius 12, one soft colour per section: green for Lesson, clay for Lina, gold for Sketchbook, blue for Accessibility, neutral for More.
  • Values (“On”, “1×”, “English”, “Large”, “Off”) are 16/600 at 55 % ink on the right; chevrons at 25 % ink only on rows that push.
  • Reset progress: its own card, centred, --danger text, no icon, no chevron. Version line 13/600 at 40 % ink below it.

States & interactions

  • Narration, Speed and Lina’s voice all push st-voice; the values come from settings.narrationEnabled and settings.defaultPlaybackSpeed, the same keys the player reads.
  • Practice reminder shows “Off” or the schedule in words (“Weekdays 7:30”), never a raw date.
  • Toggles write settings.alsoSaveToPhotos, settings.reduceMotionOverride, settings.leftHandedLayout (all Bool, default false). Text size is read-only: it reports the current Dynamic Type category.
  • Reset progress → confirmation alert with a destructive role: “Clears lesson progress. Sketchbook photos are kept.”

What changed in v3

  • White page and white cards with 2 pt borders instead of cream inset groups; tinted 40 pt icon tiles per section so the list scans by colour Duolingo.
  • Speed is no longer an inline segmented control here; it lives with narration on st-voice so the Lesson group is three clean push rows.
  • Accessibility is inline (three rows) rather than a fourth screen; “Replay the introduction” moved under About.

Developer notes

Purpose

Narration is the one new thing in this design, so it gets one screen that explains itself with a sample rather than a paragraph. The two things a learner worries about, music and the silent switch, are answered as read-only rows.

Layout

  • Inline nav bar (56 pt, back chevron, 17/800 title); the tab bar is hidden on this push (.toolbar(.hidden, for: .tabBar)).
  • Sample card first: 48 pt .face--lg, “Your tutor” eyebrow in clay, a 56 pt clay play button, the transcript in 20/800, and the same .narration chip the player uses.
  • One list: the Narration toggle row, then a stacked Speed row with the 40 pt .seg (0.5× · 1× · 1.5×). Then a soft card stating that the written instruction always stays on screen.

States & interactions

  • Play: streams Assets/Voice/simple-house/step-1.m4a; the chip reads “Speaking” with the wave moving, the button fills clay until the clip ends. If the file is missing, hide the whole sample card.
  • Toggle → settings.narrationEnabled (Bool, default true), the single key the player’s chip also writes. Off: the face desaturates, the play button disables, the chip reads “Off”.
  • Speed → settings.defaultPlaybackSpeed (0.5 / 1.0 / 1.5, default 1.0), read by PlayerViewModel at lesson start. Speed does not re-pitch the voice; at 0.5× the clip plays once at normal rate and the stroke takes longer.
  • Audio session .ambient with [.duckOthers, .interruptSpokenAudioAndMixWithOthers]: music ducks, podcasts pause, the silent switch is honoured, a call stops narration and leaves the animation running.

What changed in v3

  • The sample leads the screen and shows Lina’s face; v1 opened with the toggle. A learner should hear the voice before deciding about it.
  • Speed moved here from the Settings root so narration and pace sit together as “how a lesson plays”. White card with 2 pt border; the play button is tactile with a 4 pt clay edge.
  • The future “Voice” picker row is gone; “Lina · English” is shown as a value on the root and stays static until a second voice exists.

SwiftUI mapping

Form { Section { SampleClipCard(lessonID: "simple-house", stepIndex: 0) }
  Section { Toggle("Narration", isOn: $narrationEnabled); Picker("Speed", selection: $defaultSpeed) { … }.pickerStyle(.segmented) }
  Section { StaysOnScreenCard() }
  Section("While a lesson plays") { LabeledContent("Other audio", value: "Lowered"); LabeledContent("Silent switch", value: "Respected") } }

Accessibility

  • When VoiceOver runs, narration never auto-plays at step start; the chip becomes an explicit “Play narration” button. The wave is .accessibilityHidden(true) and does not animate under Reduce Motion.
  • Toggle: label “Narration”, value On/Off, hint “Turns the spoken instructions on or off. The written instruction stays.” Segmented control becomes a Menu at accessibility sizes.

Open questions

  • Which ElevenLabs voice is Lina, and is its commercial licence in place before any audio ships?

Developer notes

Purpose

§30 forbids pressure-heavy streaks. A reminder is still useful for an adult with limited time, so it is opt-in, learner-scheduled, single, and explicitly consequence-free. The screen says so in its first card.

Layout

  • Inline nav bar, tab bar hidden. Toggle row first (neutral bell tile off, green tile on), the row’s subtitle is the schedule in words.
  • Off: one white card (20/800 title, 17/400 body) and a dimmed preview of the only notification the app can send.
  • On: seven day pills (flex, 48 pt tall, radius 14, green with a 3 pt deeper edge when selected), a Time row with the time as a 20/800 chip, then the live preview and one caption. Everything fits without scrolling.

States & interactions

  • Toggle on → requestAuthorization([.alert, .sound]), no badge ever; if denied, the toggle returns to off with an inline row “Notifications are off for StrokeTutor · Open Settings”. iOS asks only once, so never re-request.
  • Days are multi-select, at least one; deselecting the last turns the reminder off. The time chip opens a compact DatePicker(.hourAndMinute).
  • Every change reschedules: remove all seven reminder.weekday.N requests, then add one repeating UNCalendarNotificationTrigger per selected day. Also reschedule at launch, and cancel everything on toggle off.
  • Body text comes from the path title (“Your next house is ready.” / “…tree…”), never the lesson title. All paths done: “Your sketchbook is waiting.”
  • Keys: settings.reminderEnabled (false), settings.reminderWeekdays (JSON, [2,3,4,5,6]), settings.reminderHour 7 / …Minute 30. No “last opened” date is ever stored; nothing exists from which a streak could be computed.

What changed in v3

  • The promise (“a small note, not a streak”) is the headline of the off state, in title type, instead of a paragraph under the toggle.
  • Day pills are tactile soft tiles with an edge Duolingo rather than grey circles; the wheel picker is replaced by a compact time chip so the on state fits on one screen.
  • The separate permission-primer variant is dropped: the off card already explains what will be sent, so the system prompt can follow the toggle directly.

SwiftUI mapping

Form { Section { Toggle("Practice reminder", isOn: $reminderEnabled) }
  if reminderEnabled { Section("Days") { WeekdayPills(selection: $weekdays) }
    Section("Time") { DatePicker("Remind me at", selection: $time, displayedComponents: .hourAndMinute) }
    Section("What you’ll see") { NotificationPreview(title:body:) } }
  else { PromiseCard(); NotificationPreview().opacity(0.6) } }

Accessibility

  • Pills: label the full weekday, value selected / not selected, trait button; grouped as “Days”. At accessibility sizes they wrap to two rows rather than shrink below 44 pt.
  • The preview banner is one element: “Notification preview. A few quiet minutes with a pen? Your next house is ready.”

Open questions

  • Offer the reminder once at the end of the first lesson, or only in onboarding and here? Recommendation: onboarding and here, never unprompted afterwards.
