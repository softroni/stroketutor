Developer notes

Purpose

Watch → Draw → Confirm → Continue, and nothing else. §4 calls this interaction sacred: a step plays, the app stops, the learner copies it onto paper, the learner decides when to move on. There is no countdown and no auto-advance anywhere in this screen §31. The existing PlayerViewModel already guarantees it — .awaitingUser is only left by advanceToNextStep(), which is only called from the primary button. Never add a timer that calls it.

M7 wraps the existing player, it does not replace it. DrawingCanvasView, StepProgressDots, BigPrimaryButtonStyle, BigSecondaryButtonStyle and all of Theme stay as they are. What changes is the chrome around them: a lesson header instead of the debug top bar, a full-width sheet fitted to the drawing, a persistent reference, a narration chip, an orientation beat, one action row that never moves, and a leave/resume path.

Layout

Order top to bottom follows the plan's visual priority §31: reference (1) → canvas (2) → instruction (3) → progress (4) → primary (5) → quiet controls (6). Progress is the header dots alone; the step name and lesson title are in the ⋯ menu and the leave sheet, not on the drawing screen. Nothing on this screen moves between states: the sheet is one size, the caption is one slot, the action row is always present.

  • Why the paper is width-bound and what to do about it. Every Studio drawing lives in a 1000 × 1000 canvas but uses a fraction of it: Simple House 600 × 650, Palm Tree 517 × 634, Cat Face 910 × 690. Fitting the whole canvas into a 393 pt square, as ContentView does today, draws the house 197 pt wide. Fitting the drawing's bounds into a 393 × 438 area draws it 339 pt wide, 1.7× larger, with the same file. That is where the drawing area comes from; the tall sheet is only useful because of it.
  • Two floating overlays in a reserved band, not in “empty corners”. With bounds fitting the corners are no longer reliably empty, so the band is a layout rule instead of a content assumption. Cost: 92 pt of paper above the drawing, which reads as the top margin of a sheet.
  • The primary is always in place. While the step draws it is outlined (white fill, 2.5 pt green stroke, green label) and enabled; when the animation and the narration have both finished it fills green with the existing light haptic. The fill is the “you can go now” signal, so there is no written hint. Not disabled: disabled says “you may not” and a greyed green looks broken. Not renamed to “Continue”: “I drew it” is the one line in the app that asks something of the learner, and it is what keeps the loop watch → draw → confirm.
  • ◀ and ↻ are the plan's quiet controls at 60 pt, icon-only, labelled for VoiceOver. ↻ replays the animation and the narration together, which retires the old “Watch again” / “Replay” duplicate. ◀ is at 45 % on step 1, exactly as today. Speed, Narration & voice and Start this lesson over live in the ⋯ menu.
  • The narration chip is face + state only (wave while speaking, speaker when idle, speaker-off when muted). The word “Lina” was the only text on the paper and the face already carries the identity.
  • Caption copy is two lines at 22 pt, which is about 40 characters. The shipped instructions pack two sentences into one field; split them (step.instruction is the headline, the second sentence becomes the spoken line or the proposed step.detail). A three-line caption still fits — the slot grows and the slack absorbs it — but it should be an authoring exception, not the rule.

Fitting the drawing

StrokeShape.transform(canvas:in:) already fits a rectangle into a rectangle, centred; today the source rectangle is always (0, 0, canvas.width, canvas.height). Replace the source with the lesson's stroke bounds, computed once at load:

// PreparedTutorial — computed once, constant for the whole lesson so the paper never jumps.
/// Union of every stroke's bounding box, grown by half its line width, then by 6 % of
/// the larger side on every edge. Falls back to the full canvas for a lesson with no strokes.
var fittedBounds: CGRect {
    var box: CGRect? = nil
    for step in steps { for stroke in step.strokes {
        let r = stroke.path.boundingRect.insetBy(dx: -stroke.lineWidth / 2, dy: -stroke.lineWidth / 2)
        box = box.map { $0.union(r) } ?? r
    } }
    guard let b = box, !b.isEmpty else { return CGRect(origin: .zero, size: canvas) }
    let m = max(b.width, b.height) * 0.06
    return b.insetBy(dx: -m, dy: -m)
}

// StrokeShape — `canvas: CGSize` becomes `source: CGRect`; scale and offset are unchanged in spirit.
static func transform(source: CGRect, in rect: CGRect) -> CGAffineTransform {
    let scale = min(rect.width / source.width, rect.height / source.height)
    let offsetX = rect.minX + (rect.width  - source.width  * scale) / 2 - source.minX * scale
    let offsetY = rect.minY + (rect.height - source.height * scale) / 2 - source.minY * scale
    return CGAffineTransform(translationX: offsetX, y: offsetY).scaledBy(x: scale, y: scale)
}
  • The fit uses all steps, not the steps drawn so far, so the scale is fixed for the lesson. A pencil tip, the ghost on the orientation beat and the faded earlier steps all share it.
  • Line widths scale with the drawing (they are canvas units), so a 16-unit line is 5.4 pt wide on the house instead of 3.2 pt today. That is a feature: the ink was thin.
  • The Studio can later write the same rectangle into the file (a nullable tutorial.fit) to let an author choose a looser crop; a v1 player ignores it and computes its own.
  • The web player in web/ is untouched by this document; if it adopts the same rule the two stay pixel-consistent.

Tapping the outlined primary (skip ahead). It calls the same advanceToNextStep() after player.completeCurrentStep(): cancel the in-flight animation, set strokeProgress to 1 for the step, narration.stop(), then advance. The learner who already knows the stroke, or is redoing a lesson, gets through without waiting; the claim on the button is still theirs to make. Adding the orientation pre-state without touching the enum. Do not add a case orientation to PlayerViewModel.Phase: every switch in DrawingCanvasView and ContentView is exhaustive over four cases, and currentStepIndex/canGoToPreviousStep/completedStepUpperBound all have hand-written .idle answers that are already exactly right for “loaded, nothing drawn”. Instead:

// PlayerViewModel — three small additions, all default-compatible.
func load(_ tutorial: PreparedTutorial, startImmediately: Bool = true) {
    …                                   // unchanged body
    guard !tutorial.steps.isEmpty else { phase = .finished; return }
    guard !isDebugMode else { phase = .awaitingUser(stepIndex: 0); return }
    if startImmediately { beginStep(0) }   // otherwise stay .idle
}

/// "Begin" on the orientation beat. Idempotent; a double tap cannot skip a step
/// because beginStep sets .drawing synchronously (same reason as advanceToNextStep).
func begin() {
    guard case .idle = phase, !steps.isEmpty else { return }
    beginStep(0)
}

/// The outlined primary while .drawing: finish the step now, then the normal advance.
func completeCurrentStep() {
    guard case .drawing(let i) = phase else { return }
    stepTask?.cancel()
    strokeProgress = 1; activeStrokeIndex = steps[i].strokes.count - 1
    narration.stop()
    phase = .awaitingUser(stepIndex: i)
}

Invariants preserved: the default argument keeps every existing call site and test green; no new case; .idle still means “no step has been begun”; canGoToPreviousStep stays false; DrawingCanvasView already renders nothing for .idle. The faint finished drawing is a render concern, not a phase — add one optional parameter:

DrawingCanvasView(…, ghostAllStepsOpacity: player.phase == .idle ? 0.24 : nil)

which draws every step's strokes at that opacity and suppresses the pencil tip. It reuses the existing debugLayer geometry path with an opacity argument.

  • Header × → pl-leave sheet. Cancels narration immediately (see below) but leaves the stroke animation running behind the sheet, so “Keep drawing” returns to an unbroken step.
  • Header ⋯ → Menu with Speed: 1× ▸ (a submenu of 0.5× · 1× · 1.5×, the old cycleSpeed() exposed as a picker), Narration & voice (→ st-voice), Hide the reference, and Start this lesson over (player.restart(), confirm first — it discards nothing but is surprising mid-lesson). Restart is the plan's sixth-priority control §31 and does not deserve a permanent button; speed joined it because it is a preference set once, not a per-step action.
  • Reference thumbnail → a .sheet with .presentationDetents([.medium, .large]) showing the photo and the finished sketch side by side plus the catalog objective. Playback and narration continue behind the sheet; pausing one but not the other would desync ink and voice, and pausing both would need a resume affordance the plan does not want.
  • Narration chip is the mute control. Tapping it toggles @AppStorage("narrationMuted") and, if it was playing, stops the current file. It never re-starts audio mid-step; unmuting takes effect on the next beginStep or on ↻.
  • ◀ / ↻ map 1:1 to goToPreviousStep() and replayCurrentStep(). Both work in .drawing and .awaitingUser.
  • Haptics. UIImpactFeedbackGenerator(style: .light), prepare() on entering .drawing, impactOccurred() when the primary fills. That is the only haptic in the player. The last step fires UINotificationFeedbackGenerator().notificationOccurred(.success) instead, once, as sk-complete appears. No haptic for replay, back, mute or the reference sheet — they are navigational, not achievements §30.

Voice & narration

One recorded file per step, shared/Assets/Voice/<lessonId>/<stepId>.m4a (AAC, mono, 48 kbps — a 12 s line is ~70 KB, so all five Simple House lines ship in under 400 KB). step.voiceover in the schema holds the relative path when the Studio writes one; fall back to the convention when it is null.

@MainActor final class NarrationPlayer: NSObject, AVAudioPlayerDelegate {
    private var player: AVAudioPlayer?
    var onFinish: (() -> Void)?

    /// Returns false when there is no audio for this step.
    @discardableResult
    func play(lessonId: String, step: PreparedStep, muted: Bool) -> Bool {
        stop()
        guard !muted, let url = Self.url(lessonId: lessonId, step: step) else { return false }
        activateSession()
        player = try? AVAudioPlayer(contentsOf: url)
        player?.delegate = self
        player?.rate = 1.0                     // never touched by the speed control
        return player?.play() ?? false
    }

    func stop() { player?.stop(); player = nil }

    private func activateSession() {
        let s = AVAudioSession.sharedInstance()
        try? s.setCategory(.ambient, mode: .spokenAudio,
                           options: [.duckOthers, .interruptSpokenAudioAndMixWithOthers])
        try? s.setActive(true)
    }
    func deactivate() {
        try? AVAudioSession.sharedInstance()
              .setActive(false, options: .notifyOthersOnDeactivation)
    }
}

File missingplay() returns false. The step plays exactly as it does today and the chip is hidden entirely for that step — not greyed, because grey means “you muted this”. Log once per lesson, never alert. A lesson with no voice at all is a valid, shippable lesson.

Speed affects the animation only. speedMultiplier divides stroke.duration and is never applied to AVAudioPlayer.rate. At 0.5× a recorded voice becomes a drawl and at 1.5× it loses intelligibility for exactly the audience the product is for; pitch correction would still change Lina's character. The voice is the constant, the ink is the variable — so at 0.5× the voice simply finishes first and the fill waits for the ink.

When the primary fills. After the last stroke of the step and after narration has finished — whichever is later. Why both: if the button fills while Lina is still talking, learners tap it and lose the “how” (the written line carries what, the voice carries how); if the voice ends first, filling it over a half-drawn line invites copying an incomplete shape. The outlined button is tappable throughout; the fill is only the signal. Implement inside runStep's tail rather than in the view:

// PlayerViewModel
private var strokesFinished = false
private var voiceFinished   = true      // true when muted or no file

private func beginStep(_ index: Int) {
    …                                   // unchanged: phase = .drawing set synchronously
    strokesFinished = false
    voiceFinished = !narration.play(lessonId: id, step: steps[index], muted: isMuted)
    narration.onFinish = { [weak self] in self?.voiceFinished = true
                                          self?.settleIfReady(index) }
}

// end of runStep(_:)
strokesFinished = true
settleIfReady(index)

private func settleIfReady(_ index: Int) {
    guard case .drawing(index) = phase, strokesFinished, voiceFinished else { return }
    phase = .awaitingUser(stepIndex: index)
}

Two safety rails: (1) arm a 6 s watchdog from strokesFinished that forces voiceFinished = true, so a corrupt or over-long file can never trap a learner in .drawing; (2) the guard case .drawing(index) means a late audio callback from an abandoned step cannot flip a step the learner has already left. When narration is muted, voiceFinished starts true and the timing is byte-for-byte today's behaviour.

Captions are not optional. The written instruction is always on screen, in every state, at 22 pt under the sheet. Audio is a second channel, never the only one.

Narration script — Simple House (the ElevenLabs source)

Adult voice, second person, no praise, no exclamation marks. The written line says what; the spoken line adds how and why. Target 8–14 s so the voice lands inside or just after the stroke duration.

Leaving and resuming

  • Persist { lessonId, stepIndex, updatedAt } — nothing else. One JSON file in Application Support behind a tiny ProgressStore, not @AppStorage, because path progress needs the same store.
  • Write on step boundaries only: when .awaitingUser(i) is entered, record stepIndex = i. A step is atomic; a learner interrupted halfway through the roof should be handed the roof again, not a half roof.
  • Also write on leave (belt and braces) and clear on completion.
  • Resume lands on hp-preview, whose Start becomes Continue from step 3 plus a quiet Start from the beginning. See pl-leave variant resume.
  • Continue does player.load(tutorial, startImmediately: false) then a new func jump(to index: Int) { beginStep(index) }. Steps 1–2 appear already faded on the paper because completedStepUpperBound derives from the phase, so no extra state is needed.
  • The orientation beat is skipped on resume. It is a “before you start” beat; replaying it on every return would be nagging.

Accessibility

  • Dynamic Type. Caption: .font(.system(size: 22, weight: .bold, design: .rounded)) → .custom(…, size: 22, relativeTo: .title3) so it scales. Button labels are capped at .accessibility2 (.dynamicTypeSize(...DynamicTypeSize.accessibility2)) so a 68 pt primary never wraps to four lines; the caption itself is not capped.
  • The sheet yields height. Its height is available − caption − actionRow, recomputed from the measured caption each layout pass and floored at 300 pt (the drawing area is then 208 pt, still above the 220 pt canvas floor of the old layout in effective size because of the bounds fit). Below that floor the column scrolls — the existing ScrollView with .scrollBounceBehavior(.basedOnSize) already does this, so it stays. At dynamicTypeSize.isAccessibilitySize the action row wraps: ◀ ↻ on one line, the primary full-width beneath, and the reference thumbnail grows to 88 pt.
  • Reduced motion §31: the stroke still draws — it is the teaching, and removing it removes the lesson. What changes under @Environment(\.accessibilityReduceMotion): stroke durations × 0.6 (a snappier but still continuous draw); pencil tip rendered without its trailing highlight; the narration wave freezes to five static bars; the primary's outline-to-fill is a plain 0.15 s crossfade; the sheet never animates its own size (it already never does). Offer stepwise — each stroke appearing in three instant segments with a 0.25 s beat between — as a st-access option for learners who cannot track continuous motion at all.
  • VoiceOver. Canvas: .accessibilityLabel("Step 2 of 5, the roof, drawing") while .drawing, flipping to "Step 2 of 5, the roof, drawn" on .awaitingUser; .accessibilityValue(step.instruction). Post AccessibilityNotification.Announcement("Step drawn. Draw it on your paper, then tap I drew it.") on that transition, because a VoiceOver user gets no visual cue that the animation stopped.
  • Reading order is not the visual order: .accessibilitySortPriority puts the caption first, then the sheet, then the primary, then ◀ and ↻, then the chips. Sighted priority is reference-first; non-sighted priority is text-first.
  • Labels: × “Close lesson”; ⋯ “More options”; thumbnail “Reference photo. Double tap to expand.”; chip “Narration, Lina, on. Double tap to mute.” / “Narration off. Double tap to turn it on.”; primary “I drew it” with .accessibilityValue("Lina is still drawing") while outlined and no value once filled; ◀ “Previous step”; ↻ “Watch this step again”; ⋯ “More options. Speed, narration, restart”. StepProgressDots already collapses to one element labelled “Step 2 of 5.”; leave it.
  • Tap targets: every control ≥ 60 pt (Theme.minimumTapTarget). The 76 pt thumbnail and the ~48 pt chip both clear it; the chip gets .contentShape(Rectangle()) padded to 60 pt.
  • Contrast: caption ink #2B2B2B on the page #EDEBE6 is 11.4:1; the outlined primary's green #1C8F5C on white is 4.6:1 at 24 pt heavy; the warm chip carries no text, and its state is repeated in the ⋯ menu.
  • No hidden gestures §31: there is no swipe-to-advance, no long press, no pinch. Every action has a visible, labelled control.

Orientation, landscape and iPad

  • iPhone supports landscape in the player (pl-landscape), and nowhere else in the app. The sheet turns with the phone: in portrait a tall subject draws larger (Palm Tree 317 × 389 pt against 265 × 325 in landscape), in landscape a wide one does (Cat Face 416 pt wide against 358). Which way is better is the subject's shape, so the learner chooses by turning the phone, with no setting and no prompt. §31 says consider landscape “when it materially improves reference + drawing visibility”; with bounds fitting it does, for about half the catalog.
  • UISupportedInterfaceOrientations stays portrait-only for the app; the player's fullScreenCover hosts a UIHostingController subclass that returns .allButUpsideDown from supportedInterfaceOrientations, and calls setNeedsUpdateOfSupportedInterfaceOrientations() on appear and disappear. The rest of the app never rotates.
  • A rotation must not restart the step. The animation is driven by strokeProgress, which is view-model state and survives relayout; DrawingCanvasView recomputes the transform from the new rect each pass, so an in-flight withAnimation(.linear) simply continues at the new size. Do not call replayCurrentStep() from onChange(of: geometry.size). Narration is untouched by rotation.
  • Branch on verticalSizeClass == .compact for the landscape iPhone layout, on measured width for iPad (see pl-ipad), never on UIDevice.current.userInterfaceIdiom.
  • Backgrounding: scenePhase == .background → player.stop() and narration.stop(). Returning shows the step paused mid-draw; resume by replayCurrentStep() on .active only if the phase is still .drawing, so the learner never returns to a frozen half-line.

Open questions

  • Skip ahead while drawing. The outlined primary is enabled so an experienced learner is never held by the animation. The plan's loop is “watch → draw → confirm”; a first-time learner who taps early skips the watch. Alternative: keep it enabled but require a second tap within 2 s (“Tap again to skip”) for the first three lessons only. Recommendation: ship it enabled and plain; the wording “I drew it” is enough of a check.
  • Fit margin. 6 % is drawn here. The Studio's own preview should adopt the same rule so authors see what learners see; decide whether the file records an explicit fit rectangle or the player always computes it.
  • Does every lesson get an orientation beat? Simple House earns one. Lesson 2 (“House With Chimney”) reuses the same idea and would be padding. Proposal: the beat appears only when the tutorial carries a non-empty orientation string, so it is an authoring decision in the Studio, not a runtime one.
  • Silent switch. Decided for this design: .ambient, respected (see the handbook). The counter-argument stands and is worth a creator's call: a learner who props the phone beside the paper with the switch on gets a silent lesson and may not know why; .playback (what Maps does for spoken guidance) would avoid that at the cost of speaking on a silenced phone.
  • Does speed persist? Now that speed lives in the ⋯ menu it reads as a preference; persist it (settings.defaultPlaybackSpeed already exists) rather than resetting per PlayerViewModel.
  • Schema additions needed if you accept the layout: step.detail (the second sentence) and tutorial.orientation / orientationDetail; optionally tutorial.fit. All nullable, all ignorable by v1 players. Studio would also need a sixth voice line per lesson for the orientation beat — or the beat stays silent, which is defensible since it is not a drawing step.
  • Reference photos do not exist yet for Simple House (lessons.json has no reference block; M6 is gated on photos). Until one lands, the thumbnail should be replaced by the finished sketch rather than shown as an empty frame — decide whether that is acceptable for a first release or whether Simple House waits for a photo.
  • Mid-step interruption on resume. We snap back to the start of the interrupted step. Confirm that is right for a learner who had already drawn most of it — an alternative is to resume at the step after the last confirmed one, which is what the stored index already is.

Purpose

In portrait the iPad has the iPhone's proportions and gets the iPhone's anatomy, scaled: one full-width sheet, one caption, one action row.

Layout — landscape (1180 × 820)

  • Three columns inside 24 pt margins, 28 pt gutters: 240 reference · flexible paper · 320 caption and controls. At 1180 pt that leaves 516 × 698 pt of paper (radius 32, hairline, no chip band); the house draws 445 pt wide, 2.3× the old iPhone paper and 1.3× the new one.
  • The header (×, title, ⋯) sits above the paper only, inside the centre column, so it does not stretch 1180 pt across an otherwise calm screen. iPad is the one place the lesson title is shown during play: there is room, and the left column already names the subject.

Adaptivity

  • Choose the layout from the measured container width, not the idiom: width ≥ 1000 && width > height → three columns; 700..<1000 (portrait iPad, ⅔ Split View) → the compact stack with sheet height from the available height and the reference back as a thumbnail; < 700 (½ and ⅓ splits, Slide Over) → the iPhone layout verbatim. Developer notes

Purpose

Leaving mid-lesson is normal — most lessons are 3–5 minutes but real life is not §7. The sheet exists to make one promise (“your place is kept”) that the app then keeps, so that leaving never feels like losing work. It is not a guilt gate §30: no “are you sure you want to give up?”, no streak warning, no count of what is unfinished.

Layout

  • Leave sheet. .sheet with .presentationDetents([.height(320)]) over the live player. Page-coloured, radius 32 top corners, grabber, 20 pt gutters, safe-bottom + 12 below. Title 22 pt bold, body 17 pt regular at 55 % ink.
  • “Keep drawing” is the primary and it is Theme.ink, not green. Green is reserved for the one action that moves a learner forward Duolingo; staying put is the safe default here, not progress. “Leave” is a 17 pt text button with no destructive red — nothing is destroyed.
  • The player stays fully rendered behind the 45 % scrim (sheet, caption, action row), so it is obvious there is something to come back to.
  • Resume. A green tint card between the objective and the buttons: headline “You left off at step 3”, sub-line “step.title · relative date”, and compact dots on the trailing edge so the amount left is visible without reading. Primary becomes “Continue from step 3”; “Start from the beginning” is a quiet muted text button — available, never suggested.

States & interactions

Data

  • ProgressStore holds { lessonId: String, stepIndex: Int, updatedAt: Date } per lesson, plus the per-path “furthest unlocked lesson” that hp-path needs. One JSON file in Application Support, written atomically; no CloudKit, no account §32.
  • Written when .awaitingUser(i) is entered (step boundaries only) and again on Leave. Cleared when the lesson completes.
  • “Continue from step 3” shows stepIndex + 1. The stored index is the step the learner was on, not the last one they finished, so the number in the button is the number they will see in the player header — this must match or the promise reads as broken.
  • Relative date via RelativeDateTimeFormatter (“yesterday”, “3 days ago”). If updatedAt is older than 30 days, drop the date rather than saying “2 months ago”, which reads as a reprimand §30.
  • A stored stepIndex that is out of range for a re-authored tutorial (steps removed in an update) clamps to the last valid step; never crash, never silently restart.

Voice & narration

  • Narration stops the instant × is tapped and does not resume with the sheet. If the learner taps “Keep drawing” and we replay the step, the voice replays with it — the two are always started together.
  • On Leave, deactivate the audio session with .notifyOthersOnDeactivation so any ducked music returns to full volume.
  • The mute preference is global and survives leaving; it is not per-lesson state.

Accessibility

  • The sheet is a modal: VoiceOver focus moves to “Leave this drawing?” on presentation, and the player behind is .accessibilityHidden(true).
  • Labels: “Keep drawing” and “Leave this lesson. Your place is kept.” — the reassurance belongs in the label too, because a VoiceOver user reaching the button may not have heard the body text.
  • Escape gesture (two-finger scrub) dismisses the sheet as “Keep drawing”.
  • The resume card is one accessibility element: “You left off at step 3 of 5, Put in the door, yesterday.” The trailing dots are .accessibilityHidden(true) since they repeat it.
  • Dynamic Type: the sheet's detent is .height(320) at default sizes but must become .medium at accessibility sizes, or the two buttons get cropped. Use .presentationDetents(dynamicTypeSize.isAccessibilitySize ? [.medium] : [.height(320)]).
