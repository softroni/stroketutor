Developer notes

Purpose

Watch → Draw → Confirm → Continue, and nothing else. §4 calls this interaction sacred: a step plays, the app stops, the learner copies it onto paper, the learner decides when to move on. There is no countdown and no auto-advance anywhere in this screen §31. The existing PlayerViewModel already guarantees it — .awaitingUser is only left by advanceToNextStep(), which is only called from the primary button. Never add a timer that calls it.

M7 wraps the existing player, it does not replace it. DrawingCanvasView, StepProgressDots, BigPrimaryButtonStyle, BigSecondaryButtonStyle and all of Theme stay as they are. What changes is the chrome around them: a lesson header instead of the debug top bar, a persistent reference, a narration chip, an orientation beat, and a leave/resume path.

Layout

Order top to bottom follows the plan's visual priority §31: reference (1) → canvas (2) → instruction (3) → progress (4) → primary (5) → quiet controls (6). Progress is folded into the header dots plus the card's “Step 2 of 5 · Add the roof” eyebrow, so it never competes with the instruction for weight.

// PlayerViewModel — two small additions, both default-compatible.
func load(_ tutorial: PreparedTutorial, startImmediately: Bool = true) {
    …                                   // unchanged body
    guard !tutorial.steps.isEmpty else { phase = .finished; return }
    guard !isDebugMode else { phase = .awaitingUser(stepIndex: 0); return }
    if startImmediately { beginStep(0) }   // otherwise stay .idle

/// "Begin" on the orientation beat. Idempotent; a double tap cannot skip a step
/// because beginStep sets .drawing synchronously (same reason as advanceToNextStep).
func begin() {
    guard case .idle = phase, !steps.isEmpty else { return }
    beginStep(0)
}

Invariants preserved: the default argument keeps every existing call site and test green; no new case; .idle still means “no step has been begun”; canGoToPreviousStep stays false; DrawingCanvasView already renders nothing for .idle. The faint finished drawing is a render concern, not a phase — add one optional parameter:

DrawingCanvasView(…, ghostAllStepsOpacity: player.phase == .idle ? 0.24 : nil)

which draws every step's strokes at that opacity and suppresses the pencil tip. It reuses the existing debugLayer geometry path with an opacity argument.

  • Header × → pl-leave sheet. Cancels narration immediately (see below) but leaves the stroke animation running behind the sheet, so “Keep drawing” returns to an unbroken step.
  • Header ⋯ → Menu with Start this lesson over (player.restart(), confirm first — it discards nothing but is surprising mid-lesson), Narration & voice (→ st-voice), Hide the reference. Restart is the plan's sixth-priority control §31 and does not deserve a permanent button.

Playback and narration continue behind the sheet; pausing one but not the other would desync ink and voice, and pausing both would need a resume affordance the plan does not want.
  • Narration chip is the mute control. Tapping it toggles @AppStorage("narrationMuted") and, if it was playing, stops the current file. It never re-starts audio mid-step; unmuting takes effect on the next beginStep or on “Watch again”.
  • Back / Replay / Speed map 1:1 to goToPreviousStep(), replayCurrentStep(), cycleSpeed(). Back is disabled at 40 % opacity on step 1, exactly as today.
  • Haptics. UIImpactFeedbackGenerator(style: .light), prepare() on entering .awaitingUser, impactOccurred() on “I drew it”. That is the only haptic in the player. The last step fires UINotificationFeedbackGenerator().notificationOccurred(.success) instead, once, as sk-complete appears. No haptic for replay, back, speed, mute or the reference sheet — they are navigational, not achievements §30.

Voice & narration

One recorded file per step, shared/Assets/Voice/<lessonId>/<stepId>.m4a (AAC, mono, 48 kbps — a 12 s line is ~70 KB, so all five Simple House lines ship in under 400 KB). step.voiceover in the schema holds the relative path when the Studio writes one; fall back to the convention when it is null.

@MainActor final class NarrationPlayer: NSObject, AVAudioPlayerDelegate {
    private var player: AVAudioPlayer?
    var onFinish: (() -> Void)?

    /// Returns false when there is no audio for this step.
    @discardableResult
    func play(lessonId: String, step: PreparedStep, muted: Bool) -> Bool {
        stop()
        guard !muted, let url = Self.url(lessonId: lessonId, step: step) else { return false }
        activateSession()
        player = try? AVAudioPlayer(contentsOf: url)
        player?.delegate = self
        player?.rate = 1.0                     // never touched by the speed control
        return player?.play() ?? false
    }

    func stop() { player?.stop(); player = nil }

    private func activateSession() {
        let s = AVAudioSession.sharedInstance()
        try? s.setCategory(.ambient, mode: .spokenAudio,
                           options: [.duckOthers, .interruptSpokenAudioAndMixWithOthers])
        try? s.setActive(true)
    }
    func deactivate() {
        try? AVAudioSession.sharedInstance()
              .setActive(false, options: .notifyOthersOnDeactivation)
    }
}

Silent switchRespected (.ambient). A learner who silenced the phone did not consent to a voice, and the written instruction carries the step on its own. The cost: iOS gives no API to read the switch, so the chip animates while nothing is heard. Mitigation: the onboarding line and the st-voice row both say “If your phone is on silent, Lina stays quiet”, and the chip's wave is a small hint, not the only sign a step is playing. The alternative (.playback, as Maps does) is recorded as an open question for the creator.
Phone call / SiriObserve AVAudioSession.interruptionNotification. On .began: stop the voice, treat it as “voice finished” for the gating rule below, leave the strokes drawing. On .ended: do not auto-resume; the chip returns to idle and “Watch again” is the way back.
Route change (headphones out)AVAudioSession.routeChangeNotification with .oldDeviceUnavailable → stop, same as an interruption.
File missingplay() returns false. The step plays exactly as it does today and the chip is hidden entirely for that step — not greyed, because grey means “you muted this”. Log once per lesson, never alert. A lesson with no voice at all is a valid, shippable lesson.

Speed affects the animation only. speedMultiplier divides stroke.duration and is never applied to AVAudioPlayer.rate. At 0.5× a recorded voice becomes a drawl and at 1.5× it loses intelligibility for exactly the audience the product is for; pitch correction would still change Lina's character. The voice is the constant, the ink is the variable — so at 0.5× the voice simply finishes first and the button waits for the ink.

When “I drew it” appears. After the last stroke of the step and after narration has finished — whichever is later. Why both: if the button lands while Lina is still talking, learners tap it and lose the “how” (the written line carries what, the voice carries how); if the voice ends first, showing the button over a half-drawn line invites copying an incomplete shape. Implement inside runStep's tail rather than in the view:

// PlayerViewModel
private var strokesFinished = false
private var voiceFinished   = true      // true when muted or no file

private func beginStep(_ index: Int) {
    …                                   // unchanged: phase = .drawing set synchronously
    strokesFinished = false
    voiceFinished = !narration.play(lessonId: id, step: steps[index], muted: isMuted)
    narration.onFinish = { [weak self] in self?.voiceFinished = true
                                          self?.settleIfReady(index) }
}

// end of runStep(_:)
strokesFinished = true
settleIfReady(index)

private func settleIfReady(_ index: Int) {
    guard case .drawing(index) = phase, strokesFinished, voiceFinished else { return }
    phase = .awaitingUser(stepIndex: index)
}

Two safety rails: (1) arm a 6 s watchdog from strokesFinished that forces voiceFinished = true, so a corrupt or over-long file can never trap a learner in .drawing; (2) the guard case .drawing(index) means a late audio callback from an abandoned step cannot flip a step the learner has already left. When narration is muted, voiceFinished starts true and the timing is byte-for-byte today's behaviour.

Captions are not optional. The written instruction is always on screen, in every state, at 22 pt. Audio is a second channel, never the only one.

Narration script — Simple House (the ElevenLabs source)

Adult voice, second person, no praise, no exclamation marks. The written line says what; the spoken line adds how and why. Target 8–14 s so the voice lands inside or just after the stroke duration.

Leaving and resuming

  • Persist { lessonId, stepIndex, updatedAt } — nothing else. One JSON file in Application Support behind a tiny ProgressStore, not @AppStorage, because path progress needs the same store.
  • Write on step boundaries only: when .awaitingUser(i) is entered, record stepIndex = i. A step is atomic; a learner interrupted halfway through the roof should be handed the roof again, not a half roof.
  • Also write on leave (belt and braces) and clear on completion.
  • Resume lands on hp-preview, whose Start becomes Continue from step 3 plus a quiet Start from the beginning. See pl-leave variant resume.
  • Continue does player.load(tutorial, startImmediately: false) then a new func jump(to index: Int) { beginStep(index) }. Steps 1–2 appear already faded on the paper because completedStepUpperBound derives from the phase, so no extra state is needed.
  • The orientation beat is skipped on resume. It is a “before you start” beat; replaying it on every return would be nagging.

Accessibility

  • Dynamic Type. Instruction: .font(.system(size: 22, weight: .bold, design: .rounded)) → .custom(…, size: 22, relativeTo: .title3) so it scales. Eyebrow relative to .subheadline, hint to .footnote. Button labels are capped at .accessibility2 (.dynamicTypeSize(...DynamicTypeSize.accessibility2)) so a 68 pt primary never wraps to four lines; the instruction itself is not capped.
  • The canvas yields height. Recompute side from the measured card height each layout pass, floor at 220 pt (the value already in portraitCanvasSide). Below that floor the column scrolls — the existing ScrollView with .scrollBounceBehavior(.basedOnSize) already does this, so it stays. At dynamicTypeSize.isAccessibilitySize the control row becomes a VStack of three full-width rows and the reference thumbnail grows to 88 pt.
  • Reduced motion §31: the stroke still draws — it is the teaching, and removing it removes the lesson. What changes under @Environment(\.accessibilityReduceMotion): stroke durations × 0.6 (a snappier but still continuous draw); pencil tip rendered without its trailing highlight; the narration wave freezes to five static bars; the card's .move(edge:).combined(with: .opacity) transition becomes a plain 0.15 s crossfade; the canvas never animates its own size (it already never does). Offer stepwise — each stroke appearing in three instant segments with a 0.25 s beat between — as a st-access option for learners who cannot track continuous motion at all.
  • VoiceOver. Canvas: .accessibilityLabel("Step 2 of 5, the roof, drawing") while .drawing, flipping to "Step 2 of 5, the roof, drawn" on .awaitingUser; .accessibilityValue(step.instruction). Post AccessibilityNotification.Announcement("Step drawn. Draw it on your paper, then tap I drew it.") on that transition, because a VoiceOver user gets no visual cue that the animation stopped.
  • Reading order is not the visual order: .accessibilitySortPriority puts the instruction card first, then the canvas, then primary, then the quiet row. Sighted priority is reference-first; non-sighted priority is text-first.
  • Labels: × “Close lesson”; ⋯ “More options”; thumbnail “Reference photo. Double tap to expand.”; chip “Narration, Lina, on. Double tap to mute.” / “Narration off. Double tap to turn it on.”; primary “I drew it” (no hint needed); “Watch again”; and the three existing labels kept verbatim — “Previous step”, “Replay this step”, “Speed 1×. Tap to change.” StepProgressDots already collapses to one element labelled “Step 2 of 5.”; leave it.
  • Tap targets: every control ≥ 60 pt (Theme.minimumTapTarget). The 76 pt thumbnail and the ~48 pt chip both clear it; the chip gets .contentShape(Rectangle()) padded to 60 pt.
  • Contrast: instruction ink #2B2B2B on white is 13.4:1; the 55 % eyebrow is 5.3:1; the warm chip #C4653A on #F8E7DD is 3.6:1 — acceptable for 15 pt bold, and the chip never carries information that is not also in the header menu.
  • No hidden gestures §31: there is no swipe-to-advance, no long press, no pinch. Every action has a visible, labelled control.

Orientation, landscape and iPad

  • Lock iPhone to portrait. UISupportedInterfaceOrientations = portrait only; UISupportedInterfaceOrientations~ipad = all four. Reasons: in landscape a 393 × 852 device gives 393 pt of height minus 54 + 34 safe area, so the paper can be at most ~270 pt tall while the 68 pt primary, the 60 pt row and a 22 pt instruction fight over the same 700 pt width — every element gets worse. The reference, which is the only thing landscape would buy §31, is already permanently on screen as the thumbnail. And the learner has the phone propped beside paper: an accidental rotation mid-step would re-lay-out and visibly disturb a running animation. §31 says consider landscape “when it materially improves reference + drawing visibility” — on iPhone it does not; on iPad it does, which is pl-ipad.
  • iPad split view. Branch on measured width and horizontalSizeClass, never on UIDevice.current.userInterfaceIdiom. ≥ 1000 pt and landscape → the three-column pl-ipad layout. 700–1000 pt (⅔ split) → the iPhone stack with the paper at up to 480 pt and the reference back in its thumbnail. < 700 pt (½ and ⅓ splits, Slide Over) → the iPhone layout verbatim. Never lock orientation on iPad.
  • A size change must not restart the step. The animation is driven by strokeProgress, which is view-model state and survives relayout; DrawingCanvasView recomputes scale from the new rect each pass, so an in-flight withAnimation(.linear) simply continues at the new size. Do not call replayCurrentStep() from onChange(of: geometry.size).
  • Backgrounding: scenePhase == .background → player.stop() and narration.stop(). Returning shows the step paused mid-draw; resume by replayCurrentStep() on .active only if the phase is still .drawing, so the learner never returns to a frozen half-line.

Open questions

  • “Watch again” and “Replay” are the same call. Both run replayCurrentStep(). The brief asks for both and they are both drawn here, but two controls for one action on a screen this deliberate is a flaw. Recommendation: keep Watch again as the card-adjacent secondary in .awaitingUser, and change the quiet row to Back · Speed · Restart — restart is the plan's own sixth-priority control and currently has no home except the ⋯ menu. Needs your call before build.
  • Does every lesson get an orientation beat? Simple House earns one. Lesson 2 (“House With Chimney”) reuses the same idea and would be padding. Proposal: the beat appears only when the tutorial carries a non-empty orientation string, so it is an authoring decision in the Studio, not a runtime one.
  • Silent switch. Decided for this design: .ambient, respected (see the handbook). The counter-argument stands and is worth a creator's call: a learner who props the phone beside the paper with the switch on gets a silent lesson and may not know why; .playback (what Maps does for spoken guidance) would avoid that at the cost of speaking on a silenced phone.
  • Does speed persist? Today it resets with each PlayerViewModel. A learner who prefers 0.5× will re-set it every lesson. Suggest persisting it; it is a preference, not a per-lesson state.
  • Schema additions needed if you accept the layout: step.detail (the hint line) and tutorial.orientation / orientationDetail. Both nullable, both ignorable by v1 players. Studio would also need a sixth voice line per lesson for the orientation beat — or the beat stays silent, which is defensible since it is not a drawing step.
  • Reference photos do not exist yet for Simple House (lessons.json has no reference block; M6 is gated on photos). Until one lands, the thumbnail should be replaced by the finished sketch rather than shown as an empty frame — decide whether that is acceptable for a first release or whether Simple House waits for a photo.
  • Mid-step interruption on resume. We snap back to the start of the interrupted step. Confirm that is right for a learner who had already drawn most of it — an alternative is to resume at the step after the last confirmed one, which is what the stored index already is.

Developer notes

Purpose

The plan asks for the real-world reference “side-by-side where practical” §31. On iPad it is practical, so the expandable thumbnail and its sheet do not exist here: the photo and the finished sketch are simply always visible. Nothing is hidden behind a tap.

Layout

  • Three columns inside 24 pt margins, 28 pt gutters: 260 reference · flexible paper · 340 instruction and controls. At 1180 pt that leaves 476 pt for a square canvas, which is 1.45× the iPhone paper.
  • The header (×, title, ⋯) sits above the canvas only, inside the centre column, so it does not stretch 1180 pt across an otherwise calm screen.
  • Progress moves to the right column as full-size StepProgressDots (16/24 pt) directly under the instruction — it has room here, so it does not need the compact header treatment.
  • The narration chip is a real element in the right column above the primary button, not a canvas overlay. There is no reason to float it over the paper when a column has spare height.
  • Controls keep the iPhone's exact order and sizes: primary 68 pt, secondary 60 pt, quiet row 60 pt. A learner who switches devices should find the same buttons in the same relationship.
  • Left column bottom carries the objective (lessons.json.objective) at 15 pt, 55 % ink — the “why” that the iPhone can only show inside the reference sheet.

States & interactions

  • Identical state machine, identical timing rule, identical narration behaviour. The only per-phase difference: while .drawing, the primary and “Watch again” are absent and the right column's spacer grows, exactly as on iPhone.
  • No reference sheet, no expand badge, no showReference state on this layout.
  • Tapping the photo still opens a full-bleed version (.fullScreenCover) for close inspection — optional, and the only hidden affordance on the screen, so it gets a visible i-expand badge on hover/focus and a VoiceOver hint.

Adaptivity

  • Choose the layout from the measured container width, not the idiom: width ≥ 1000 && width > height → three columns; 700..<1000 → the iPhone stack with an up-to-480 pt paper and the reference back as a thumbnail; < 700 → the iPhone layout verbatim. This makes Split View, Slide Over and Stage Manager fall out for free.
  • iPad is never orientation-locked. In portrait (834 × 1194) the two-column split has no room, so it uses the ≥ 700 branch: iPhone stack, bigger paper.
  • A width change must not restart the step — see pl-player → Orientation, landscape and iPad.
  • At accessibility type sizes the three-column layout collapses to the stack even at full width; 340 pt cannot hold a 34 pt instruction plus three buttons.

Developer notes

Purpose

Leaving mid-lesson is normal — most lessons are 3–5 minutes but real life is not §7. The sheet exists to make one promise (“your place is kept”) that the app then keeps, so that leaving never feels like losing work. It is not a guilt gate §30: no “are you sure you want to give up?”, no streak warning, no count of what is unfinished.

Layout

  • Leave sheet. .sheet with .presentationDetents([.height(320)]) over the live player. Page-coloured, radius 32 top corners, grabber, 20 pt gutters, safe-bottom + 12 below. Title 22 pt bold, body 17 pt regular at 55 % ink.
  • “Keep drawing” is the primary and it is Theme.ink, not green. Green is reserved for the one action that moves a learner forward Duolingo; staying put is the safe default here, not progress. “Leave” is a 17 pt text button with no destructive red — nothing is destroyed.
  • The player stays fully rendered behind the 45 % scrim, so it is obvious there is something to come back to.
  • Resume. A green tint card between the objective and the buttons: headline “You left off at step 3”, sub-line “step.title · relative date”, and compact dots on the trailing edge so the amount left is visible without reading. Primary becomes “Continue from step 3”; “Start from the beginning” is a quiet muted text button — available, never suggested.

States & interactions

× tappednarration.stop() immediately (a voice talking under a modal is disorienting); the stroke animation keeps running; sheet presented.

Swipe-to-dismiss the coverDisabled. .interactiveDismissDisabled(true) on the fullScreenCover, so a lesson can only be left through the × and this sheet. That is the one place a gesture is taken away, and it is taken away to protect the learner's place.

Data

  • ProgressStore holds { lessonId: String, stepIndex: Int, updatedAt: Date } per lesson, plus the per-path “furthest unlocked lesson” that hp-path needs. One JSON file in Application Support, written atomically; no CloudKit, no account §32.
  • Written when .awaitingUser(i) is entered (step boundaries only) and again on Leave. Cleared when the lesson completes.
  • “Continue from step 3” shows stepIndex + 1. The stored index is the step the learner was on, not the last one they finished, so the number in the button is the number they will see in the player header — this must match or the promise reads as broken.
  • Relative date via RelativeDateTimeFormatter (“yesterday”, “3 days ago”). If updatedAt is older than 30 days, drop the date rather than saying “2 months ago”, which reads as a reprimand §30.
  • A stored stepIndex that is out of range for a re-authored tutorial (steps removed in an update) clamps to the last valid step; never crash, never silently restart.

Voice & narration

  • Narration stops the instant × is tapped and does not resume with the sheet. If the learner taps “Keep drawing” and we replay the step, the voice replays with it — the two are always started together.
  • On Leave, deactivate the audio session with .notifyOthersOnDeactivation so any ducked music returns to full volume.
  • The mute preference is global and survives leaving; it is not per-lesson state.

Accessibility

  • The sheet is a modal: VoiceOver focus moves to “Leave this drawing?” on presentation, and the player behind is .accessibilityHidden(true).
  • Labels: “Keep drawing” and “Leave this lesson. Your place is kept.” — the reassurance belongs in the label too, because a VoiceOver user reaching the button may not have heard the body text.
  • Escape gesture (two-finger scrub) dismisses the sheet as “Keep drawing”.
  • The resume card is one accessibility element: “You left off at step 3 of 5, Put in the door, yesterday.” The trailing dots are .accessibilityHidden(true) since they repeat it.
  • Dynamic Type: the sheet's detent is .height(320) at default sizes but must become .medium at accessibility sizes, or the two buttons get cropped. Use .presentationDetents(dynamicTypeSize.isAccessibilitySize ? [.medium] : [.height(320)]).

Open questions

  • Where does “Leave” land? Drawn here as hp-preview (the screen the learner came from). The alternative is hp-path, which shows the progress they just made in context. Needs a decision with the Home & paths owner.
  • Should the Learn tab's continue card also offer “Continue from step 3”? It would mean two entry points to the same saved place. Recommend yes, using the identical string, since a learner who left mid-lesson will look at the home screen first.
  • Confirmation on leaving the very first step? There is nothing to keep at step 1, so the sheet arguably should not appear at all before the first “I drew it”. Cheap to add, and it removes a pointless question from the very first lesson.
  • Does a resumed lesson still count as “finished today” for the optional reminder (st-reminder)? Out of scope here, but the store needs to answer it.
