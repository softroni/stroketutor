Developer notes

Purpose

Cover the launch gap with something that already teaches the visual language. No logo lockup, no gradient splash: paper, ink, one line.

Layout

  • Background --paper (#FAF7F0), not --page — the launch screen is a sheet of paper.
  • Mark block centred optically: the 260×98 pen line, the 40 pt/800 wordmark, a 15 pt subhead at --ink-55. Nothing else, no version string.

States & interactions

  • Static frame = LaunchScreen.storyboard. A storyboard renders before any of our code runs, so it cannot animate and cannot read Dynamic Type. It must contain the finished line and the wordmark as a static composition (an asset-catalog image plus a label, or a single PDF vector image).
  • Animated frame = the first SwiftUI view (SplashView), laid out pixel-identically to the storyboard so the hand-off is invisible; it re-draws the same path over 2.4 s with a trim animation.
  • Minimum on-screen time 0.9 s, maximum 1.6 s; if the catalog is ready earlier we still hold to 0.9 s so it never flickers. Then: hasCompletedOnboarding == false → ob-1; otherwise → hp-home.
  • No tap is required in the real app. The mockup makes the body tappable only so the document can be clicked through.

Data

Reads one value, @AppStorage("hasCompletedOnboarding") var hasCompletedOnboarding = false. Nothing is written here.

What onboarding persists (whole group)

KeyType / defaultWritten by
hasCompletedOnboardingBool, falseob-ready only, on either exit button
selectedPathIdString, "houses"ob-8 Continue

  • Deliberately four keys and no onboardingStep: the flow is under a minute, so an interrupted run restarts at ob-1 rather than resuming mid-story.
  • Because hasCompletedOnboarding is written last, a learner who force-quits at beat 6 sees onboarding again — the intended behaviour.
  • Replay: Settings → “Show the introduction again” (st-settings) presents the same flow in a .fullScreenCover with isReplay = true: the Skip affordance becomes “Done”, ob-8 pre-selects the stored selectedPathId, and ob-ready dismisses the cover instead of routing. No stored value is cleared by replaying.

Accessibility

  • The storyboard frame cannot scale with Dynamic Type; keep the wordmark a vector image so it is crisp at every scale and let the SwiftUI view take over before any text needs to scale.
  • VoiceOver: the whole splash is one element labelled “Paper Coach”, .accessibilityAddTraits(.isHeader); the line is .accessibilityHidden(true).
  • Reduce Motion: skip the trim animation and show the completed line with a 0.2 s opacity fade. §31

SwiftUI mapping — the flow container

Recommendation: a NavigationStack of OnboardingStep values, not a TabView(.page).

enum OnboardingStep: Int, Hashable, CaseIterable {
    case problem, blankPage, whatToNotice, fromPhoto,
         method, whatYouNeed, progress, choosePath, voice, ready
}

struct OnboardingFlow: View {
    @State private var path: [OnboardingStep] = []
    var body: some View {
        NavigationStack(path: $path) {
            BeatView(.problem, advance: advance)
                .navigationDestination(for: OnboardingStep.self) { BeatView($0, advance: advance) }
        }
        .toolbar(.hidden, for: .navigationBar)   // the rail replaces the nav bar
        .interactiveDismissDisabled()
    }
}
  • Why not TabView(.page): paging keeps neighbouring beats alive, so the stroke animations on beats 4, 5 and 7 start while the page is still off-screen and are half-finished when it arrives; a half-completed drag also desyncs the rail; and free swiping lets a learner skim past the choice on beat 8. §31 “minimise hidden gestures”
  • Why a stack: each beat is pushed fresh, so onAppear is exactly the moment the drawing should begin; back is one explicit chevron; the order is programmatic, so Skip is path = [.choosePath] and nothing else changes.
  • Keep .navigationBarBackButtonHidden(true) but leave the interactive pop gesture on — it mirrors the chevron rather than replacing it.
  • The rail is one OnboardingRail(progress:onBack:onSkip:) in a .safeAreaInset(edge: .top), so every beat body gets the same 52 pt of chrome without repeating it.

Open questions

  • Do we want the same line animation on every cold launch, or only on the first launch of a session? Repeated 2.4 s animations become a tax on a daily user — proposal: animate on first launch of the day, static otherwise.

iOS will ask for permission next. If you say no, the reminder simply stays off — nothing else changes.

The sample is the first sound the app ever makes, and only because the learner asked for it. The caption under the chip is the step instruction verbatim — audio is a second channel, never the only one.

Developer notes

Purpose

Introduce the recorded voice once, hand over the switch, and offer a reminder that cannot become pressure. §30 tone: no pressure-heavy streak mechanics

Layout

  • Two cards, each a 36 pt tinted icon tile + 17 pt title + 51×31 toggle, with a 13 pt muted explanation underneath. The warm tile is Lina’s colour; the reminder tile is neutral until it is on.
  • “Hear a sample” is a 60 pt secondary button inside the card, not a primary — the primary on this screen is Continue.

States & interactions

  • Spoken guidance is on by default and writes narrationEnabled immediately (no Save). Turning it off greys the sample button’s icon but leaves the button usable, so a learner can hear what they turned off.
  • Sample: plays simple-house/walls.m4a (~4 s), shows the .narration chip with the moving wave and prints the instruction below it. While playing, the button becomes “Play it again”. Respects the silent switch: category .playback with .duckOthers, so music dips instead of stopping; never interrupts a call; if the ringer is silenced the chip shows and the caption is the whole experience.
  • Reminder is off by default. Turning it on reveals the time row (default 19:30, editable inline with a DatePicker(.hourAndMinute)).
  • Notification permission is requested exactly here, and nowhere else in the flow: on the on transition of this toggle, immediately after the learner’s tap, with the explanatory line already visible above the system alert. Never on launch, never on the splash, never at ob-ready, never pre-emptively “to be ready later”. If the learner denies it, the toggle animates back to off, reminderTime stays -1, and a 13 pt line offers the Settings deep link (UIApplication.openSettingsURLString). If the status is already .denied from a previous install, do not call requestAuthorization again — go straight to that line.
  • Continue → ob-ready. Both toggles are already persisted by the time it is tapped.

Data

  • @AppStorage("narrationEnabled") = true — the same key st-voice and the player read; there is one source of truth for the mute state.
  • @AppStorage("reminderTime") = -1 (minutes after midnight; -1 = off). On a successful grant, schedule one repeating UNCalendarNotificationTrigger with identifier practice-reminder; on off, remove that identifier and set -1.
  • Notification copy is plain and un-guilted: “Five minutes and a pen.” Body: “Lesson 4 of Houses is ready when you are.” Never “Don’t break your streak”, never a count of missed days, never written in Lina’s voice unless the learner opted in. §30

Voice & narration — Lina’s lines

The recorded script for the whole first run (ElevenLabs, produced in the Studio; files shared/Assets/Voice/onboarding/<beat>.m4a). In v1 the flow is silent and only the sample on this screen plays — the app should not speak before the learner has been shown the switch. The lines are written and recorded now so the narrated flow needs no rewrite.

BeatSpoken line
ob-1“There is a moment when you see something and think: I would like to draw that.”
ob-2“And then the page is empty, and you don’t know where the first line goes.”
ob-3“I’m Lina. Drawing gets easier once you know what to notice — and what to leave out.”
ob-4“A photograph. The simple forms underneath it. A finished drawing. That is the whole journey.”
ob-5“I draw one small step. You copy it onto your paper. When you are ready, you tell me to go on. Nothing moves before you do.”
ob-6“Five minutes, a pen, and a sheet of paper. That is all you need.”
ob-7“This is the first house in the Houses path, and one from later in the same path. Same pen, same five minutes.”
ob-8“So — what would you like to learn first? You can change this whenever you like.”
ob-voice“I’ll talk you through each step while it draws. You can turn my voice off whenever you like.”
ob-ready“Your first lesson is ready. Get your paper, and I will meet you there.”

Direction for the recording: unhurried, mid-range, a small smile, no upward inflection at the end of sentences. Between 2 and 7 seconds each. Nothing in the script congratulates the learner for something they have not done yet.

Accessibility

  • VoiceOver order: rail → bubble → “Spoken guidance, on, switch” → the explanation → “Hear a sample, button” → reminder card → Continue.
  • The .narration chip is .accessibilityHidden(true) while the caption below carries the text; a moving wave has nothing to say to VoiceOver.
  • Toggles are real Toggles: they inherit switch traits, Voice Control names and Full Keyboard Access for free.
  • Dynamic Type: the bubble grows first; both rows wrap title above toggle at accessibility sizes rather than squeezing the 51 pt switch; the body scrolls with Continue pinned.

SwiftUI mapping

@AppStorage("narrationEnabled") private var narrationEnabled = true
@AppStorage("reminderTime")     private var reminderMinutes = -1   // -1 = off

Toggle("A gentle reminder", isOn: $reminderOn)
  .onChange(of: reminderOn) { _, on in
      guard on else { reminderMinutes = -1; Reminders.cancel(); return }
      Task {
          let granted = await Reminders.requestAuthorization()   // the ONLY call site
          if granted { reminderMinutes = 19 * 60 + 30; Reminders.schedule(reminderMinutes) }
          else { reminderOn = false; showSettingsHint = true }
      }
  }

Open questions

  • Should the flow itself be narrated once narrationEnabled is known — i.e. does the learner ever hear beats 1–8? Recommend no for v1: a voice that starts before the switch is offered is exactly the surprise this screen exists to avoid.
  • Default reminder time: 19:30 is a guess. Ask at the same moment (“morning or evening?”) or leave the picker to do the work?

Developer notes

Purpose

Convert the choice into a concrete first act. Not a congratulation screen: the learner has not done anything yet. One calm sentence, one lesson, one button. §30 tone

Layout

  • Rail at 100 % with a live back chevron — going back to change the path is a reasonable thing to want here.
  • Headline, Lina at lina--sm (she hands over and leaves), then one white card: path chip + position chip, the 192 pt canvas, and the lesson name with its two honest facts (time, steps). No objective paragraph — that belongs to hp-preview, one tap away, and repeating it here would make this screen a duplicate preview.
  • Bottom: 68 pt green “Start drawing”, then a 17 pt text button. The quiet option is genuinely quiet but not hidden.

States & interactions

  • Both buttons write hasCompletedOnboarding = true before routing — “Look around first” is a legitimate finish, not an escape, and must never cause the flow to replay on the next launch.
  • “Start drawing” → hp-preview for paths[selectedPathId].lessonIds.first (Simple House), so the learner still sees the reference and the objective before the player opens. §7 lesson anatomy
  • “Look around first” → hp-home with the Learn tab active; the continue card there shows the same lesson, so nothing is lost by choosing it.
  • The onboarding cover is dismissed, not pushed away from: the tab bar appears for the first time on the screen underneath.
  • In replay mode (from Settings) both buttons simply dismiss the cover and leave every stored value alone.

Data

  • Everything on the card derives from selectedPathId: path title and icon from paths.json, lesson title, estimatedMinutes and steps.count from lessons.json / the tutorial file. Choosing Trees on beat 8 shows Palm Tree, 16 steps, here — so the copy must not assume five steps.
  • The drawing is the tutorial’s own strokes rendered complete; there is no separate “final image” asset. §5 “the completed tutorial strokes are the final illustration”

Voice & narration

Silent. If the narrated flow ships, this is the one line worth hearing in her voice, because it is the hand-off to the player, where her voice is the only place she exists.

Accessibility

  • VoiceOver order: rail → headline → bubble → “Houses, lesson 1 of 10. Simple House, about 4 minutes, 5 steps.” (the card is one element; the canvas is hidden) → “Start drawing, button” → “Look around first, button”.
  • Dynamic Type: the canvas shrinks to a 140 pt floor, then the body scrolls; both buttons stay pinned and never collapse into one.
  • Reduce Motion: the drawing appears complete.

SwiftUI mapping

@AppStorage("hasCompletedOnboarding") private var done = false

BigPrimaryButton("Start drawing") { done = true; route = .preview(firstLesson) }
Button("Look around first")       { done = true; route = .home }
    .buttonStyle(.quietText)

Open questions

  • Should this screen offer “Remind me instead” for a learner who has no pen to hand right now? It is honest, but it hands the last moment of onboarding to a deferral. Recommend not.
  • Cross-links hp-preview and hp-home belong to group B; the ids are taken from the screen map.
