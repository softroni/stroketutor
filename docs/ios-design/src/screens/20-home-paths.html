Developer notes

Purpose

One screen, one question: what do I draw next? §29 asks Home to “ask what the learner wants to sketch and show calm progress across subject paths”. The hero answers it in one tap; the paths below let the learner change their mind. §30 forbids streaks, XP and daily goals, so there is no counter on this screen that can go down.

Layout

  • Scrolling content (.screen-body--scroll) between the status bar and a three-tab bar with Learn active. 20 pt gutters, 12 pt between stacked blocks.
  • Hero card (.card, radius 28): eyebrow “Continue” in green 13 pt/800, a 104 pt .thumb of the next lesson's finished drawing, title 22 pt/700, then two quiet meta lines, then the single green 68 pt primary. The finished drawing is deliberately shown before the lesson starts — it is step 2 of the lesson anatomy §7, not a spoiler.
  • Path cards: 44 pt icon tile, title, a 6 pt .progress--thin bar and “n of m drawn”. Calm on purpose — no percentage, no badge, no colour coding.
  • More paths is a secondary button, not a card, so it never competes with a path the learner owns.
  • The sketchbook line is a 44 pt text row at the very bottom: a fact, not a target.
  • Lina does not appear here. She belongs to onboarding, the narration chip and completion; a tutor on the home screen every launch would read as mascot-driven motivation §30.

States & interactions

  • first-time — straight out of ob-ready. Nothing is started, so there is no “Continue”: the hero is lesson 1 of the chosen path, the path card carries the description instead of a progress bar, and the sketchbook line becomes an honest empty line.
  • in-progress — hero = the next unlocked lesson of currentPathId. Tapping Start → hp-preview; a path card → hp-path; More paths → hp-paths.
  • Path finished (not drawn): if the current path has no next lesson, the hero becomes “You have drawn every house in this path” with Choose another path → hp-paths. See hp-path variant complete.
  • No content: if the bundle yields zero lessons the hero is replaced by a plain card, “No lessons are installed. Reinstalling the app restores them.” — never an empty hero.
  • Nothing on this screen animates on appear. Progress bars are static; they change only after a completion.

Data

  • Where content comes from. Tutorials ship as a folder reference named Tutorials (TutorialLoader.bundleSubdirectory), discovered with bundle.urls(forResourcesWithExtension:"json",subdirectory:) — dropping a new lesson in needs no code change. shared/Catalog/ (paths.json, lessons.json) must be added to the same target in M7. today the app does not read the catalog at all: TutorialLibrary loads every bundled file and sorts it alphabetically by title, so there is no path, no order and no unlock rule in the shipped app yet.
  • Field by field. Path title ← paths.json.title; path lesson count ← lessonIds.count; lesson title ← tutorial.title (Simple House); step count ← tutorial.steps.count; time ← formatMinutes(estimateLearnerSeconds(tutorial)), the placeholder formula in web/src/catalog/metrics.ts: animation × 3 + 8 s × steps. Port it to Swift once so Studio and app always agree.
  • Progress. A local Progress store keyed by lessonId holding completedAt: Date (plus photoId? for the sketchbook). No account, no sync §32. Suggested storage: one JSON file in Application Support, loaded once into an @Observable ProgressStore. “n of m drawn” = path.lessonIds.filter(progress.isDone).count.
  • Next lesson = the first id in path.lessonIds order that is not done. That single rule drives the hero, the green row in hp-path and the unlock state of everything after it.
  • Current path = the path of the most recently completed lesson, falling back to the path chosen in onboarding. Stored as currentPathId in UserDefaults.
  • Mock vs catalog. paths.json publishes one lesson per path today (houses: ["simple-house"], trees: ["palm-tree-4"]); the 10 and 8 shown here are the Appendix A curriculum the catalog is growing into. The screen must read the counts, never hardcode them.

Voice & narration

  • Silent screen. No narration, no sound on tap. Lina's voice starts inside the player, at the first step.
  • The mute state lives in settings and is read here only to decide nothing — it is not surfaced on Home.

Accessibility

  • Dynamic Type: every label scales (.title2, .subheadline, .footnote via Theme.rounded); the 104 pt thumbnail and the 44 pt icon tile stay fixed and the row grows around them. At accessibility sizes the hero's thumbnail + text row wraps to a vertical stack (ViewThatFits), and the path rows keep the icon but drop the progress bar's caption onto its own line. Nothing truncates.
  • VoiceOver: the hero is one element — “Continue. Small Cottage, lesson 3 of 10, Houses, about 4 minutes, 7 steps”, action “Start”. Path card: “Houses, 2 of 10 drawn” with the progress bar hidden (.accessibilityHidden) because the caption already says it. Sketchbook line: “6 drawings in your sketchbook”, trait button.
  • Reduced motion: nothing to disable here; the pulse ring lives on hp-path only.
  • Tap targets: hero primary 68 pt, rows and the sketchbook line ≥ 44 pt, cards ≥ 60 pt (Theme.minimumTapTarget).

Developer notes

Purpose

Switching subject is a first-class action §6 — “across paths, users can switch freely” — so this is a plain browse list, not a settings screen buried three taps down. It also has to tell the truth about a catalog that is still being written.

Layout

  • Nav bar with a back chevron to hp-home; the tab bar stays, because this is inside the Learn tab.
  • Rows are cards, 60 pt minimum: 44 pt icon tile, title 17 pt/700, one-line description 13 pt, then (started paths only) a 6 pt progress bar and “10 lessons · 2 drawn”.
  • Two sections. Open now = paths with at least one published lesson. Being drawn = the rest of the §6 candidate set, on a flat 55 % white, icon at 45 % opacity, a neutral .chip reading “Not yet”, no chevron and no tap. Showing them is a promise about direction; greying them is the honest half of that promise.
  • The footnote refuses the obvious dark pattern: no “notify me”, no e-mail capture §32.
  • iPad: the same rows in two columns inside a 900 pt measure, centred. One column past ~700 pt of width, two above it (AdaptiveColumns / size class).

States & interactions

  • Available row → hp-path for that path. Selecting a path does not reset anything; it sets currentPathId only when the learner actually starts a lesson from it.
  • Unavailable row: not a button. allowsHitTesting(false), no chevron, no highlight. VoiceOver reads it and says “not available yet”; it is not marked as a button.
  • A path whose lessons are all drawn shows “10 of 10 drawn” with a gold check instead of the bar.
  • If the catalog fails to load, the whole list is replaced by the content-problem state owned by st-system — never a blank list.

Data

  • Rows come from paths.json in file order. Open now = lessonIds non-empty and at least one of those tutorials loaded. Being drawn = the remaining candidate paths.
  • gap paths.json today has title, lessonIds and — for Houses only — description. Trees has no description, and the eight future paths are not in the file at all. M7 needs: (a) a required one-line description on every path, (b) an icon name per path so the app stops mapping ids to SF Symbols in code, and (c) unpublished paths present in the catalog with lessonIds: [] so this screen is data-driven rather than a hardcoded “coming soon” array.
  • Descriptions in this mock for the eight unpublished paths are written from the §6 progression-emphasis table; Houses' line is the real paths.json description, shortened to its first clause. The row shows description truncated to one line with .lineLimit(1) — the full text lives on hp-path.
  • gap palm-tree-4.json is schemaVersion 2 and the shipped app reads version 1 only (TutorialLoader.isForNewerApp silently skips it). Until the app gains v2 (colour fills), Trees would be empty in the real build even though the catalog publishes it. “Open now” must therefore be computed from tutorials that actually loaded, not from the catalog alone.

Accessibility

  • Dynamic Type: descriptions may wrap to two lines at larger sizes; the row grows, the 44 pt icon tile does not. At accessibility sizes the icon moves above the title.
  • VoiceOver: “Houses. From a front-facing house to a small street scene. 10 lessons, 2 drawn. Button.” / “Flowers. A simple bloom, then stems and layered petals. Not available yet.” Section headers use .accessibilityAddTraits(.isHeader).
  • Rotor: both sections are headings, so a VoiceOver user can jump past the eight unavailable paths.

Developer notes

Purpose

§29 asks Path Detail for “ordered progression, next available lesson, completed lessons, future locked lessons, and destination examples”. All five are on the first fold: the destination card, the count, the two gold rows, the green row.

Layout

  • Title 28 pt/800 + paths.json.description at 15 pt (the full text — this is the one place it is not truncated).
  • Destination card: a gold chip “Where this path leads”, a 112 pt finished drawing of the last lesson, and one line of why. It is not tappable — tapping would land on a locked lesson.
  • Count + bar: “2 of 10 drawn” / “8 to go”, then a 6 pt bar. No percentage.
  • Lesson rows, one .list, dividers between: 28 pt number badge, 46 pt finished drawing (done rows only), title 17 pt/700, one meta line.
    StateBadgeRowTrailingTap

  • A thumbnail in a row means one thing only: a drawing you have made. The next lesson and the locked ones carry none, so the gold rows read as a record rather than a catalogue — and the destination is shown once, in its own card, instead of twice.
  • The row is 60 pt minimum; the green row is taller because of its button. Exactly one green thing on the screen Duolingo — that is the whole “current node” idea, rewritten for an adult who wants to scan.

States & interactions

  • default — 2 done, 3 next, 4–10 locked.
  • locked — tapping any locked row raises a detent sheet (.presentationDetents([.height(260)])) naming the lesson that must come first. One action, “Go to Small Cottage” → hp-preview; swipe down or tap outside dismisses. No “unlock” offer, no store: locking is a teaching decision, not a paywall §6. The tapped row stays visibly pressed behind the sheet.
  • complete — the count block is replaced by a calm card; there is no green primary because there is nothing to start. “See them in your sketchbook” → sk-book; “Choose another path” is a quiet text button at the end. The destination card becomes “Where this path led”.
  • Scroll position on push: top. Returning from a completed lesson, scroll to the new green row (ScrollViewReader.scrollTo(nextLessonId, anchor: .center)) with a 0.3 s ease — the one motion on this screen, and it is skipped under Reduce Motion.
  • Appending lessons to a path later must not invalidate prior completion §6: progress is keyed by lessonId, never by index.

Data

  • The unlock rule, computed, never stored: 
    func isUnlocked(_ lessonId: String, in path: Path) -> Bool {
  guard let i = path.lessonIds.firstIndex(of: lessonId) else { return false }
  return i == 0 || path.lessonIds[..<i].allSatisfy(progress.isDone)   // sequential, per path
}
    The blocking lesson named in the sheet is the first not-done id before the tapped one. Paths are independent: Trees 5 and Houses 2 at the same time is normal §6.
  • Row order = paths.json.lessonIds order. The number badge is the index + 1; it is display only.
  • Title ← tutorial.title; “About 4 min · 7 steps” ← formatMinutes(estimateLearnerSeconds) + steps.count; “Drawn 6 September” ← Progress[lessonId].completedAt, .dateTime.day().month(.wide), no year inside the current year.
  • The done-row thumbnail is the StrokeTutor drawing rendered from the tutorial's strokes (a Canvas at full strength), not the learner's photo — the photo belongs to the sketchbook. Cache by lessonId; ten of them are cheap because they are paths, not bitmaps.
  • gap Houses publishes one lesson today, so the real screen currently shows one row and no destination. The destination card must hide itself when the last lesson is also the next one.
  • content simple-house.json already ends with a chimney step, which is Appendix A's lesson 2 idea. Either lesson 1 should stop after the windows or lesson 2 needs a different new idea; otherwise the path teaches the same thing twice.

Accessibility

  • VoiceOver: rows are single elements. “Small Cottage, lesson 3 of 10, next. About 4 minutes, 7 steps. Button.” / “Simple House, lesson 1 of 10, drawn 6 September. Button.” / “House From an Angle, lesson 4 of 10, locked. Finish Small Cottage first. Button.” — the reason is in the label, so a VoiceOver user never has to open the sheet to learn it.
  • The sheet takes focus on appear and returns it to the tapped row on dismiss.
  • Dynamic Type: titles and meta scale; the 46 pt thumbnail and 28 pt badge stay fixed and rows grow. At accessibility sizes the green row stacks its Start button below the text, full width, 60 pt.
  • Reduce Motion: the breathing ring becomes a static 3 pt green ring; the scroll-to-next jump is instant. The ring is never the only signal — colour, the number and the Start button all carry it, which also covers colour-blind learners.
  • iPad: the list holds a 700 pt measure centred; on a wide window the destination card moves into a right-hand column beside the list (ViewThatFits / HSplitView-style two-column).

Developer notes

Purpose

The four things §29 asks for — reference photo, final sketch, approximate time, one concise objective — plus the honest “what you need”, because the whole product depends on the learner having paper in front of them §4. One green button. Nothing else on this screen moves the learner forward.

Layout

  • The pair: two 1:1 tiles, 170 pt each, 12 pt apart, each with a 13 pt label above. Reference left, drawing right — the reading direction is the lesson's argument: this real thing becomes these lines. Under the photo, the credit at 13 pt/35 % ink.
  • Title 28 pt/800, then chips: clock + time, step count. Objective on a flat card at 17 pt/500 — body size, because it is the one sentence worth reading.
  • Lina appears once, small (64 pt), to explain the method in one line. She is not on Home or in the path; here she is setting expectations for a first-timer §30.
  • The primary sits in a fixed .bottom-area above the home indicator, never inside the scroll — on the smallest phone the learner can always see it.
  • Portrait only. The player handles landscape §31. On iPad the pair grows to 260 pt tiles inside a 700 pt measure.

States & interactions

  • default — Start drawing → pl-player variant drawing. Back → the path.
  • replay — reached from a gold row. The chip states the date, the primary becomes Draw it again with a replay glyph, a secondary offers the sketchbook, and Lina's intro is dropped: a learner who has drawn it does not need the method explained again. Drawing it again does not remove the first page — it adds a second one, so the learner can compare (a “valuable future moment” in §7).
  • No reference photo: the pair collapses to a single full-width finished drawing and the credit line is omitted. The screen must never show an empty grey tile.
  • Resume: if a run of this lesson was interrupted (pl-leave), the primary reads “Continue from step 3” and a quiet text button offers “Start over”.
